# Design GPT UI Skills

使用当前 ChatGPT / Codex 会话的内置图像生成工具设计整套 UI。**不需要填写 API Key，不调用中转生图接口。**

## 工作流程

1. 生成首页候选，选定首页母版。
2. 参考母版生成其余页面，保持整套一致。
3. 展示完整图片集，由用户确认。
4. 先看全套，再按八部分输出开发说明。
5. 根据素材清单裁切干净素材，记录原图、坐标和用途。
6. 用户需要开发且已指定技术栈时，再进入实现。

也支持直接分析与裁切用户上传的已确认 UI 套图，不必重新生图。

## 八部分交付

整套 UI 概览、逐页结构拆解、公共组件与差异、视觉规范及 Design Tokens、交互与状态、素材清单、响应式与实现建议、最终交付清单。

可见事实、估算、推测、待确认及建议补充分开标记。分析未指定技术栈时提供通用方案。

裁图只提取照片、插画、封面、纹理和特殊品牌素材。文字、按钮、卡片和导航由组件实现。无法干净提取或缺少透明版时，明确列出待原始素材，不假装已经抠图。

## 使用

将整个仓库目录安装到所用客户端的 skills 目录，保留 `SKILL.md`、`references/`、`scripts/` 和 `agents/`。具体安装目录由客户端决定。

示例：

> 使用 $generate-pages-from-homepage 为我的微信小程序生成整套 UI，直接调用当前会话的内置生图能力。整套图让我确认后，输出八部分开发说明，并按素材清单裁图。

> 这套上传的 UI 图片我已经确认，请先查看全套，再逐页分析，提取 Design Tokens 和公共组件，裁切可用于开发的独立素材。

如果客户端**没有开放内置生图工具**，安装 skill 不会凭空增加生图能力。这时可继续分析已有图片；不要要求用户填写 Key。客户端还需支持读取技能说明和图片。

## 文件

- `SKILL.md`：阶段与确认规则。
- `references/image-generation.md`：原生生图与图片引用。
- `references/ui-analysis.md`：八部分分析要求及表格。
- `references/asset-slicing.md`：裁图规范与坐标清单。
- `references/implementation-quality.md`：可选代码实现标准。
- `scripts/crop_assets.py`：精确矩形裁图、边界校验与来源记录。
- `scripts/normalize_image.py`：可选尺寸工具，不自动用于 UI 页面。
- `runtime.local.json`：不含密钥的流程默认值，不是 API 客户端配置。

实际裁图需要本地原图、Python 3.10+ 和 Pillow；这些只用于处理已有图片，不用于调用生图服务。坐标按原图像素记录，不能用预览缩放后的坐标。

运行裁图前先阅读裁图规范，建立真实的 crop-plan；执行 `--dry-run` 校验后再导出。没有文件访问能力时仍可输出分析，但必须如实标明素材导出待完成。
